# Network avatar pose synchronization

The generated network player prefab uses GlimpTagNetworkAvatarPoseSync to replicate the owner's head and two hand poses.

## How it works
- The local XR camera and tracked hand proxy transforms are sampled in player-root local space.
- A single INetworkSerializable snapshot carries the head, left hand, and right hand position/rotation.
- The owner writes the snapshot to an owner-writable NetworkVariable.
- The default send rate is 20 snapshots per second.
- Remote avatars smooth toward the latest snapshot instead of snapping on every network update.
- The owner sees local tracked hand spheres; remote clients see a simple body, head, and hand proxy model.

## Prefab generated by the Editor
GlimpTagNetworkPrefabBuilder creates Assets/Resources/GLIMP_TAG/NetworkPlayer.prefab and wires:
- Root NetworkObject, Rigidbody, CapsuleCollider, GlimpTagNetworkPlayer, GlimpTagOwnerNetworkTransform, GlimpTagNetworkAvatarPoseSync, and GlimpTagNetworkPlayerRig.
- Local camera, XR camera driver, XR hand input, hand-contact locomotion, and a small start menu.
- Local hand trigger colliders with GlimpTagNetworkTagger.
- Remote-only body/head/hand visuals and hand colliders.
- A NetworkManager and UnityTransport in the main scene.
- A temporary XR lobby camera that is disabled while the local player camera is active and restored after leaving or disconnecting.
- The existing forest spawn points are used to place each owner's player object.

## LAN test
The lobby menu supports direct local Wi-Fi host/join only:
1. Start HOST LOCAL GAME on one headset.
2. On another headset connected to the same Wi-Fi, find the host headset's local IP in Quest Settings > Wi-Fi > connected network.
3. Enter that IP in the join field and press JOIN LOCAL GAME.

This is not internet matchmaking. Direct UDP connections may be blocked by router isolation or network policy. Unity Relay and room codes are a later step.

## Known limitations
- The prefab and scene are generated by Unity Editor code; they are not materialized as committed prefab/scene YAML assets in this source-only repository.
- NetworkVariable pose updates are not a substitute for a dedicated prediction/interpolation system; movement feel and bandwidth need testing with real devices.
- The owner-authoritative root transform is not cheat resistant.
- The simple remote avatar is primitive geometry, not a finished gorilla-style character.
- No Unity compilation, multiplayer test, cloud build, APK build, or Quest test has been run in this environment.
